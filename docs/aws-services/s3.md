# Amazon S3 — Hướng dẫn dịch vụ và thực hành

<small>STORAGE · OBJECT STORAGE · UC01 / UC02</small>

## 1. Amazon S3 là gì?

**Amazon Simple Storage Service (Amazon S3)** là dịch vụ **Object Storage** của AWS. Dữ liệu được lưu dưới dạng object trong bucket và truy cập thông qua S3 API. Một object gồm nội dung dữ liệu, key và metadata.

S3 là nền tảng phổ biến cho Data Lake, file ingestion, backup, log, static assets và machine learning datasets.

## 2. 10 WH questions — Amazon S3

| WH | Câu hỏi và giải thích |
|---|---|
| What | S3 là object storage lưu file/object trong bucket, không phải relational database hay filesystem POSIX. |
| Why | Có khả năng mở rộng lớn, độ bền dữ liệu cao theo thiết kế dịch vụ, tích hợp sâu với analytics, security, backup và ML của AWS. |
| When | Dùng cho file, data lake, backup, log, artifacts và dữ liệu chia sẻ qua API. Không dùng thay thế block device hoặc database transaction engine. |
| Where | Bucket được tạo trong một AWS Region. Cần xét data residency, service availability, latency và cross-Region transfer. |
| Who | IAM roles/users, bucket policies, access points và AWS service principals có thể được cấp quyền truy cập. |
| Which | Chọn storage class theo access frequency, retrieval latency, retention, minimum storage duration và chi phí. |
| How | Dùng Console, AWS CLI, SDK/Boto3, S3 API, DataSync, Transfer Family hoặc Infrastructure as Code. |
| How much | Các yếu tố gồm GB-month, request, retrieval, data transfer, replication, lifecycle transition và version storage. |
| What if | Xử lý AccessDenied, explicit deny, KMS permission, Region mismatch, multipart upload chưa hoàn tất, object overwrite và quota. |
| How compared | S3 là object storage; EBS là block storage; EFS/FSx là file storage. DataSync và Transfer Family giải quyết các kịch bản truyền dữ liệu chuyên biệt. |

## 3. Thành phần và khái niệm quan trọng

| Thành phần | Ý nghĩa |
|---|---|
| Bucket | Container logic chứa object; tên bucket tuân theo naming rules và namespace tương ứng |
| Object | Đơn vị dữ liệu được lưu trong S3 |
| Key | Tên định danh object trong bucket |
| Prefix | Phần đầu của key, thường dùng để tổ chức theo source, ngày hoặc dataset |
| Versioning | Lưu nhiều version của object để hỗ trợ khôi phục overwrite/delete |
| Storage class | Nhóm lưu trữ với trade-off về giá, truy cập và retrieval |
| Lifecycle | Tự động chuyển storage class hoặc expire object theo rule |
| Bucket policy | Resource-based policy kiểm soát truy cập vào bucket/object |
| Access Point | Endpoint có policy riêng giúp quản trị access ở quy mô lớn |
| Multipart upload | Chia file lớn thành nhiều part để upload song song và retry từng phần |
| Replication | Sao chép object sang bucket đích theo cấu hình |

~~~mermaid

  SRC["Local / On-prem files"] --> CLI["AWS CLI / Boto3"]

  IAM --> S3["Private S3 bucket"]

  RAW --> ETL["Glue / downstream processing"]

  CURATED --> ATHENA["Athena SQL"]
  S3 -. "Object API events" .-> CT["CloudTrail data events"]
~~~

Ví dụ cấu trúc:

~~~text
s3://<bucket-name>/
  landing/
    source_system=loan_demo/
      ingest_date=2026-09-30/
        loans.csv
  curated/
    loan_demo/
      snapshot_month=2026-09/
        part-00000.parquet
  athena-results/
  rejected/
~~~

Không đưa tên khách hàng, account number, customer identifier thật hoặc thông tin nhạy cảm vào bucket name/object key.

## 5. Cấu hình nền tảng (Core configuration)

- **Block Public Access:** giữ bật ở account và bucket, trừ use case public đã được phê duyệt rõ ràng.
- **Object Ownership:** chọn Bucket owner enforced để tắt ACL trong thiết kế mới.
- **Default encryption:** SSE-S3 là baseline đơn giản; dùng SSE-KMS khi cần customer-managed key, key policy hoặc audit/control cụ thể.
- **Versioning:** bật nếu cần khôi phục object bị overwrite/delete; cần tính cả dung lượng của các version cũ.
- **Lifecycle:** thiết kế theo retention và access pattern; kiểm tra minimum storage duration và retrieval charges.
- **Bucket policy:** dùng để thể hiện quyền truy cập resource, cross-account và yêu cầu TLS.
- **Logging/audit:** đánh giá CloudTrail data events khi cần audit object-level API; cân nhắc event volume và chi phí.

## 6. So sánh với lựa chọn thay thế

| Dịch vụ | Storage model | Khi phù hợp |
|---|---|---|
| Amazon S3 | Object | Data Lake, file, backup, artifacts |
| Amazon EBS | Block | Disk gắn với EC2 |
| Amazon EFS | NFS file | Shared filesystem cho Linux |
| Amazon FSx | Managed file systems | Windows, Lustre, ONTAP, OpenZFS workloads |
| AWS DataSync | Managed data transfer | Transfer/synchronize file hoặc object giữa hệ thống |
| AWS Transfer Family | Managed file transfer | Đối tác cần SFTP/FTPS/FTP endpoint |
| AWS Snow Family | Offline data transfer/edge | Data transfer rất lớn khi network hạn chế và thiết bị phù hợp |

**Decision rule:**
- Ứng dụng mới có thể gọi S3 API → AWS CLI/SDK.
- Đồng bộ NAS/file server hiện hữu → đánh giá DataSync.
- Đối tác cần SFTP → Transfer Family.
- Network hạn chế và lượng dữ liệu rất lớn → đánh giá Snow Family.
- Cần block device hoặc shared filesystem → EBS/EFS/FSx, không dùng S3 để giả lập filesystem.

## 8. Cost drivers

| Thành phần | Pricing dimension cần kiểm tra |
|---|---|
| Storage | GB-month theo storage class |
| PUT/COPY/POST/LIST | Request count |
| GET/HEAD | Request count |
