# Sources, diagrams and image attribution

## Source policy

Prioritize authoritative primary sources, especially AWS documentation and AWS Architecture Center. Use external image assets only when their licensing/terms permit reuse in a public GitHub repository and a public website.

**Do not hotlink random Google Images or copy images from blogs without checking permission.** Prefer:
1. Original Mermaid diagrams stored with the Markdown.
2. Editable Draw.io diagrams created for this learning project, using AWS architecture icons under their applicable brand guidelines.
3. Official AWS architecture reference diagrams and service documentation where reuse terms allow it.
4. Properly licensed images with creator, source URL, license/terms, and retrieval date recorded.

## Diagram conventions

- Every architecture diagram must have Mermaid or Draw.io source.
- Include alt text and a caption.
- Distinguish AWS-managed services, customer code, data stores, and trust boundaries.
- Avoid unsupported claims about network paths, encryption defaults, availability, or pricing.
